# 缓存规范

## 结构
```
kline_cache/
├── 600519.json      # 每股一文件，bar 列表（day 升序）
├── 000001.json
└── ...
fundamentals/
├── yjbb_2024_all.csv        # 业绩报表（某年，全市场）
└── fin_ind/000001.json      # 财务指标（按年份 key）
industry_cache.json          # {code: {industry, concepts}}
```

## bar 结构
```json
{"day":"2026-09-04","open":"13.57","high":"14.32","low":"13.56","close":"14.25","volume":"376833363"}
```
> 新浪返回为**字符串**，用前需 `float()`。

## 新鲜度
- **参考交易日** = 上证指数（sh000001）最新 bar 日期；
- 每股 `last_date == 参考交易日` ⇒ 已最新，跳过（增量核心）。

## 未复权与缺口
- 新浪日线未复权；除权/除息造成名义跳空；
- 判定：`|close_t/close_{t-1} - 1| > 0.105` ⇒ 缺口（主板 ±10%）；
- 用途：动量/收益类研究中，**排序窗口含缺口者剔除**，避免污染。

## 容量
- 单文件保留最近 **150–300** 根足够短线研究；长历史（如 1500 根）单独目录（如 `kline_ext/`），避免每日增量反复重写大文件。

## 一致性
- 所有分析脚本（回测/扫描）**统一从缓存读**，不在线边跑边拉 → 结果可复现、可离线。
